# V3DSAM — Open-Vocabulary Semantic Dense SLAM

**V3DSAM** is a feed-forward, monocular, open-vocabulary semantic dense SLAM system. It
chains three components into a single pipeline **without** online optimization of the
front-end or training a sparse loop-closure backend:

- **VGGT-SLAM** — feed-forward pose front-end (verbatim official implementation, consumed as-is)
- **SAM3** — open-vocabulary semantic segmentation
- **3DGS (Splat-SLAM)** — dense Gaussian reconstruction backend

On top of this base, V3DSAM contributes two results:

1. **Semantic-geometric 3D-consistency loop verification** (Contribution 1): back-project
   SAM3 category masks into 3D, transform loop-candidate views by their relative pose, and
   compare per-pixel semantic labels bi-directionally and symmetrically, reinforced by an
   object-level consistency criterion. This rejects false loops — "same room, reverse
   viewpoint" cases where appearance / geometry / category overlap all fail to separate.
2. **Geometry-anchored persistent instance identity** (Contribution 2): **category identity**
   ("what it is") is given by semantics; **instance identity** ("which one") is anchored by
   geometric clustering in the SL(4) globally-consistent world frame. The same physical
   object is re-identified across loop closures via overlap in world coordinates.

> 本仓库为 SCI 稿件《V3DSAM》的**最终代码**开源版，供复现两处贡献的全部实验数字。

## Key results (real data)

### Contribution 1 — semantic-geometric loop verification

| Metric | Result |
| --- | --- |
| Head-to-head (15 candidates: 11 true + 4 false) | **P = 1.0 / R = 1.0** (TP 11 / FP 0 / TN 4 / FN 0) |
| αmatch native threshold (−0.95) | P = 0.733 (FP = 4) |
| Discrimination margin | false c ≤ 0.078 vs true c ≥ 0.152 (≈2× gap); P = R = 1.0 for τ ∈ (0.078, 0.152) |
| Noise robustness | P = 1.0 at 0.2 noise; P = 1.0 / R = 0.818 at 0.5 noise |
| Trajectory gain (ATE, m) | room 0.809 → **0.074** (11×); 360 0.188 → **0.0488** |
| Compute overhead | **12.5 ms / candidate** |

### Contribution 2 — geometry-anchored persistent instance identity

| Metric | Result |
| --- | --- |
| Re-identification (geometric / category-gated / appearance) | room **89.5%** / 59.2% / 2.6%; 360 **86.6%** / 52.2% / 1.5% |
| Geometry-anchor stability (median centroid displacement, half-view split) | **≈7 cm** (vs competitor rolling Sim3 ~30 cm, ≈4× tighter) |
| Persistent instance matrix (4 scenes × 5 frames) | scene0000 = 7 / 0059 = 9 / 0106 = 12 / 0207 = 3 instances, same object = same color + same `#id` across loops |

### ScanNet long sequences

| Metric | Result |
| --- | --- |
| False-loop rate | 4 scenes, 31 candidates → **6.5%** (2/31) |
| scene0207 false-loop rejection | appearance score 0.947 but consistency 0.0 → ATE 0.109 → **0.089** |
| mIoU (200 frames) | 0.119 / pixel-acc 0.477 (structural classes 0.5–0.87; rare classes drag it down) |

All numbers are read from the real result files generated by the scripts below — no
hard-coded tables.

## Repository structure

```
V3DSAM/
├── README.md / LICENSE / .gitignore / requirements.txt / environment_sgs.yml
├── setup.sh / setup.py            # installs base deps + third_party (vggt/sam3/perception_models/salad)
├── main.py                        # VGGT-SLAM demo entry (verbatim official, + open-set query menu)
├── vggt_slam/                     # active front-end package (VGGT-SLAM 2.0, SL(4) manifold)
│   ├── solver.py / submap.py / slam_utils.py / graph.py / map.py / loop_closure.py ...
│   └── pipeline.py / stage{2,3,4}_*.py   # VGGT-SLAM → 3DGS reconstruction pipeline
├── vggt_slam_official/            # verbatim upstream reference (unmodified, for front-end audit)
├── evals/                         # TUM / EuRoC ATE evaluation
├── tools/                         # mIoU / 7-Scenes / 3DGS export utilities
├── scripts/                       # all experiment + evaluation code, grouped by function
│   ├── frontend/                  #   VGGT-SLAM stage-1 front-end + npz generation + diagnostics
│   ├── semantic/                  #   SAM3 open-vocab segmentation + semantic cloud/keyframe/instance
│   ├── loop_closure/              #   Contribution 1: loop verification, αmatch, ablations
│   ├── instance_identity/         #   Contribution 2: geometry-anchored identity, re-ID, matrices
│   ├── reconstruction/            #   3DGS backend, opacity decay, floater pruning, NVS
│   ├── evaluation/                #   mIoU / instance GT evaluation / overhead
│   ├── paper/                     #   figure generation + md→docx conversion
│   └── run/                       #   shell launchers (incl. AutoDL reproduction)
├── data/README.md                 # dataset + intermediate-artifact conventions
```

`third_party/` is **not** bundled — `setup.sh` clones `vggt` (VGGT_SPARK), `sam3`,
`perception_models`, and `salad` into it.

## Installation

```bash
# 1) Base deps + third_party (vggt / sam3 / perception_models / salad)
bash setup.sh

# 2) Model weights are pulled at runtime from HuggingFace (facebook/VGGT-1B)
#    and the SAM3 / Perception-Encoder checkpoints as described below.
```

Requirements: Python 3.10+, PyTorch 2.x + CUDA (recommended RTX 4090 / A100). The exact
conda environment is [`environment_sgs.yml`](environment_sgs.yml).

## Reproduction

### 0. Datasets

| Dataset | Use | Convention |
| --- | --- | --- |
| TUM-RGBD | front-end ATE, loop verification (9 `fr1` sequences) | `datasets/tum/{seq}/` |

See [`data/README.md`](data/README.md) for exact paths and the large intermediate artifacts
that are generated but not distributed.

### 1. Front-end + npz (VGGT-SLAM stage 1, incl. loop detection)

```bash
# Batch npz generation (what the paper's numbers are computed from):
python scripts/frontend/gen_npz_scan.py --scenes scene0000_00 ...

# Or the interactive demo:
python main.py --image_folder examples/kitchen/images/ --vis_map
```

### 2. Semantic (SAM3 open-vocab segmentation + semantic cloud)

```bash
python scripts/semantic/gen_kf_semantic.py ...
python scripts/semantic/gen_semantic_cloud_10m.py ...
```

### 3. Contribution 1 — loop verification

```bash
# The loop-verification numbers come from these three (NOT a single stub runtime):
python scripts/frontend/gen_npz_scan.py ...          # candidate extraction + poses
python scripts/semantic/semantic_3d_check.py ...     # per-pixel 3D consistency
python scripts/semantic/semantic_object_check.py ... # object-level reinforcement
# Ablations / head-to-head tables & figures:
python scripts/loop_closure/gen_scannet_alpha.py ...
python scripts/loop_closure/gen_e1_e3.py ...
python scripts/loop_closure/gen_fig3_two_row.py
```

### 4. Contribution 2 — instance identity

```bash
# Geometry-anchored instance clustering + 2D-mask ID assignment (bind_instance):
python scripts/instance_identity/gen_instance_grid_3d2d.py --scenes ...
# Re-identification head-to-head (incl. Dinya baseline):
python scripts/instance_identity/compare_instance_identity.py ...
python scripts/instance_identity/compare_dinya_reid.py ...
```

### 5. Instance evaluation (Table 4-3) & mIoU

```bash
python scripts/evaluation/eval_persistent_identity.py ...
python scripts/evaluation/eval_instance_identity_gt.py ...
python scripts/evaluation/measure_miou.py ...
```

### 6. Reconstruction (3DGS) + NVS

```bash
python vggt_slam/pipeline.py --image_dir ... --stage all --num_iters 3000
# Batch launchers: scripts/run/*.sh
```

## Consistency notes (honesty statement)

To keep this repository faithful to the manuscript, three things are made explicit:

1. **There is no single "loop-verification" runtime.** The Contribution-1 numbers are the
   output of `gen_npz_scan.py` (front-end + candidate poses), `semantic_3d_check.py`
   (per-pixel 3D consistency), and `semantic_object_check.py` (object-level reinforcement).
   An earlier `semantic_loop_verify.py` prototype was a stub and is **not** part of the
   final code path.
2. **`vggt_slam/` vs `vggt_slam_official/`.** `vggt_slam_official/solver.py` is the verbatim
   upstream `Solver` main loop, used by the front-end / loop-verification scripts to produce
   the front-end numbers. It reuses the shared core modules (`slam_utils`, `loop_closure`,
   `map`, `submap`, `graph`, …) from the active `vggt_slam` package (a reverse import), so the
   two packages are not fully separable — `vggt_slam_official` requires `vggt_slam` on the
   import path. `setup.py` installs both.
3. **Honest reporting.** Appearance-based re-ID (~2%) is reported as a *weak baseline*, not
   "indistinguishable" — the L2 appearance score is itself the retrieval signal (circular).
   Category identity = semantics, instance identity = geometry. The dense-reconstruction
   (NVS) collapse is a structural negative result of the feed-forward setting, not a method
   contribution.

All experiment numbers originate from the real JSON / markdown result files generated by
these scripts; nothing is hard-coded into the tables.
